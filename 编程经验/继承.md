继承会把父类的属性和方法都学习下来，比如我一个电脑类，一定要有硬盘和内存，我继承他们时候我需要实现这些方法，比如继承了硬盘，你需要初始化硬盘的列表。 之后你就可以直接调用这些父类的方法，好处是你定义一个硬盘标准（方法），你需要创建很多电脑实例，你创建的时候都去继承这个硬盘的标准并照着实现即可。
要不你每次新建都需要在定义一次硬盘和方法，如果又一次你定义错了名字或者方法名，导致每个实例之间不兼容就麻烦了，这里指的是每个电脑实例，如果是继承，我每次删掉硬盘我只需要固定调用一个固定名字的方法(removedisk), 但是如果你妹继承自己定义定义错了名字了比如remdisk，那么我默认去调用removedisk就会失败，造成连锁问题。

java 再抽象类方面跟python一致，但是java多一个概念是接口
接口只定义方法不实现,可以一次继承多个接口但是只能单继承抽象类. python到是可以继承多个抽象类.

从技术角度看，java完全可以做一次多继承，但是java的设计理念是担心当一次继承2个抽象，且2个抽象有同名方法时，没法很好的解决这个问题，于是直接放弃了这个实现。这个概念叫做菱形继承
              harddisk
computer A              computer B
             server X
电脑A和B都继承了硬盘，并且重写了硬盘的新建方法，这时候服务器X继承电脑A B 该用哪个硬盘的新建方法呢？
java为了防止这个问题直接放弃了多继承
            
python 使用了一个概念叫做C3 MRO
即他再多继承的时候记录了一个顺序，比如上文中档server x多继承时候，你会选择A 和B哪个放在前面， 假如 server X (A B),python默认子类方法优先
则继承的时候的顺序会是 server X->A->B-> harddisk.
当我们调用insertdisk， 他会按照这个顺序寻找这个方法，正常应该会在A里面就找到，之后就停止了， B虽然也存在但是永远不会被调用。从而解决了多继承问题。
