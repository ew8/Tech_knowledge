# Agent Skill

## 作用：  
复用已有的能力，如一个Excel分析器，好比代码中一个方法块。  
突破模型的一些限制，如知识截止时间，你可以设计一个联网搜索功能，从而搜索到最新的数据，比如黄金价格。调用代码去做数学计算（大模型是猜）。亦或是检索已有的知识库。  

## 基本构成：  
一个典型的skill文件目录如下：  
./agent-skill-case/  
- README.md 介绍文档(可选)
- How-to.md 使用文档(可选)  
- **SKILL.md 主技能（唯一必须，name + description + 流程）**
- reference.md 辅助文件（或者目录，AI按需寻找并读取，不会直接load,可选）
- examples.md 示例文件（可选）
- code 代码文件或文件夹（可选，实际为tool目录，即agent使用时可能需要的工具，如上文中联网搜索代码块，数学计算方法等）  

## Skill.md文件内容：  

第一部分： **元数据** 文件索引

以- - -包裹，用于告知agent这个skill的用处，这一部分在agent启动后会直接扫描并常驻在内存中，以供agent识别并调用。

必填name和desciption,describtion 应相对具体，否则可能导致AI无法识别并调用。例：

"- - -"  
name: 计算器
desciption：可以做加减乘除的数学运算  
"- - -"

第二部分： **正文body** 详细手册  

正文包括这个skill所有详细内容，如目标，约束，执行步骤，调用规范，参考资料，checklist，成功标准失败处理等。

即你做一件事情，这件事整个流程的内容，条件等都应尽量详细写入到正文，以便agent判断。  

建议**遵循Zero-shot原则**，即假设 AI 是一个刚入职、完全不懂业务的新人，把每一步写得像“工厂流水线操作手册”一样刻板、具体。多用“必须”、“严禁”、“如果 A 则执行 B”这样的确定词汇，少用“尝试”、“大概”、“可能”之类的模糊词汇。这样，你的 Skill 才会足够稳健。


## 如何工作:

1. 一个典型的skill会是一个文件夹，每一个agent会有一个固定的文件夹，下面有N个skill文件夹，agent会再初始化或者每个新对话发生时遍历文件夹并读取每一个skill.md的元数据部分以清楚自己拥有的能力。

2. 当用户发出问题后，agent会将用户的问题+元数据打包发给大模型以供判断，决定需要调用哪些skill（称为LLM预选）  
或  
框架有向量库的能力，将用户的信息向量化，并与向量画的skill做匹配。

3. 当agent已知需要哪些skill后，他会重新回到skill文件夹读取整个skill.md获取完整的步骤约束等信息，将他们拼接成一个上下文后，连带着用户问题发送给大模型。

4. 大模型阅读上下文后，会严格遵循约束等信息，尝试给出根据skill处理后的正确回答，或要求agent根据自己生成的参数进一步调用skill的功能，如代码。 agent根据回答判断下一步，如已获得回答则结束问题，或根据要求调用，并判断回答结果亦或进一步与大模型交互获取下一步指令，循环至获取结果以结束。

5. 当agent回答完毕一个问题，即当前轮对话结束，agent还需要进行清理工作，如刚才添加到上下文中的skill正文， 以防止上下文污染与token的爆发。



# 注：
Agent载入skill的方式不唯一：
1. **全量加载**：如果skill过多的确是初始化时只加载元数据，但是部分skill非常少的情况下，是有全量加载的玩法，即整个skill.md都被读取并分析。  
  -多agent的时候，会有一个总调度，当调度判断出应该选择哪个agent后，agent会初始化并读取skill.md所有内容
2. **懒加载**：这是正文中使用的方式，即初始化加载元数据，命中后加载overall/目标部分，之后继续下一步指令。
3. **反思与纠错**：会重新读取overview部分，比如调用技能返回了违规内容，agent框架拦截了错误，此时会重新吧overview二次投喂并强调已有的失败和overview的重要性。
